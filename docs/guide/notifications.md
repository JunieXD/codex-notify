# 通知内容与时机

`codex-notify` 发送两类飞书卡片：任务正常完成，以及任务确认中断。

## 完成通知

Codex 正常结束一轮任务后，会通过 `notify` 调用 `codex-notify`。飞书卡片包含：

- Codex 会话标题；
- 任务耗时；
- 你提交的原始任务；
- Codex 的最终回复；
- 本地发送时间。

任务和结果默认收纳在卡片内容中，既方便在手机通知栏快速判断状态，也能在飞书中查看完整结果。

## 中断通知

网络断开、服务异常、用量限制等情况可能没有正常的完成事件。后台 watcher 会增量读取 Codex 本地会话记录，并结合 `Stop` Hook 判断任务是否意外结束。

发现异常后不会立即发送消息，而是等待并再次确认任务没有自动恢复。这样可以减少短暂重连或正常结束过程中的误报。

中断卡片通常包含：

- Codex 会话标题和任务耗时；
- 原始任务；
- 已识别的错误信息；
- 任务工作目录；
- 本地发送时间。

## 为什么中断检测是“尽力而为”

中断检测依赖 Codex 写入本地会话记录。如果发生断电、系统崩溃或进程被强制结束，Codex 可能来不及记录终止信息，此时任何本地通知工具都无法可靠判断任务状态。

因此：

- 正常完成通知由 Codex 官方 `notify` 事件触发，可靠性更高；
- 中断通知通过本地记录推断，会尽量减少漏报和误报，但不能保证覆盖所有极端情况。

## 避免重复通知

同一个事件会使用稳定标识去重，`Stop` Hook 和后台 watcher 不会各自重复发送。若原有 notifier 也向飞书发送消息，两个独立工具仍可能各发一条；确认 `codex-notify` 正常后，可以停用旧工具的飞书发送功能。

## 内容过长时

飞书卡片有大小限制。`codex-notify` 会优先保留任务状态和关键信息，只在接近飞书限制时截断过长内容，避免整条通知发送失败。
